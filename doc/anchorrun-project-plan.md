# AnchorRun 远端工作区计划

更新：2026-10-13。此计划替代 2026-09-22 的“本地源码权威”设计。

## 定位

AnchorRun 是本地配置驱动的 Agent 远程工作区入口。源码、Git、模型、
数据、构建结果和环境保存在远端；本地目录可以只有 .anchorrun.yaml。
读取源码产生的文本仍会进入本地 Agent / 模型上下文。

配置声明连接、目录和镜像；CLI 执行确定性的连接、检查和容器操作；
Skill 指导 Agent 在远端读写、测试和操作 Git。本地文件工具不会自动
重定向，因此 Skill 必须明确选择远端入口。

## 第一步：配置与执行语义

- 引入 schema v2，拒绝 schema v1 并给出显式迁移说明。
- 删除 project.local_root、state_dir、sync、artifacts。
- 删除 sync、pull、--no-sync；exec 不再上传或下载目录。
- 保留配置向上发现、SSH 别名、target 选择、容器路径/设备/挂载。
- 提供合理默认值；镜像支持 tag 和 digest，在 prepare 解析实际 ID。
- 两个 target 独立，不承诺两台机器代码相同。

## 第二步：远端开发流程

- prepare 创建/复用具备所有权标签的项目容器；普通 exec 使用容器 ID。
- 配置不匹配时报错；显式 --recreate 才停止并替换受管理容器。
- 重建保留宿主机 bind mount 数据，但丢弃容器可写层，不承诺自动回滚。
- shell 为交互入口；每次 exec 明确工作目录，无隐式持久 shell 状态。
- 支持不分配 TTY 的 stdin，预检查不能吞掉补丁内容。
- 原样传递 stdout、stderr 和退出码；诊断使用 stderr。
- Skill 改为远端源码/Git 权威，示范读取、检查补丁、应用、diff 和测试。
- 保留 entrypoint 能力，但明确它用于托管容器的 shell keepalive；
  用户 exec 命令直接执行，不再由镜像应用入口解释。

## 第三步：安装、入门与验证

- 更新 README 的 CLI + Skill 安装、SSH、新目录双目标配置和日常提示词。
- 提供独立的 v1 迁移说明、配置参考和最小配置。
- 单元测试验证错误配置拒绝、容器复用/所有权/重建、输入输出和退出码。
- 从仅有配置的本地目录，实际验证两台独立远端机器。
- 验证远端 Git 补丁、错误补丁不改源码、容器状态保留、二进制 stdin、
  参数引用、目标隔离，以及整个流程没有生成本地源码/状态副本。
- 验证证据保存到 doc/validation-v2.md。
- 在独立 feature 分支提交，并创建面向 main 的 GitHub PR。

## 本次范围外

不做源码同步、产物注册表、运行级快照、完整运行账本、集群调度、
自动跨机器代码同步、长任务恢复、Web 控制台或透明本地文件工具代理。
不安装远端 AI Agent，不申请 GPU，不自动修改用户的现有项目配置。
